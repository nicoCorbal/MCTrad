## Diseño y navegación

La identidad utiliza marfil, azul tinta y el monograma `mc.`. Portada, Servicios, Sobre mí, Contacto, Tarifas, fichas, páginas legales y errores comparten tipografía y espaciado. La foto de portada lleva un marco rectangular con esquinas suaves; se eliminaron las letras y la flecha decorativas.

El catálogo enlaza a los siete tipos de documento y los servicios relacionados se seleccionan por afinidad temática. La navegación, el pie, el botón de contacto y la pantalla de carga usan CSS para sus efectos sencillos. La librería de animaciones se reserva para las páginas que todavía la necesitan. El menú móvil tiene etiquetas accesibles y admite cierre con Escape.

## Arquitectura SEO y rendimiento

Las rutas, sitemap y prerenderizado comparten el mismo inventario. Cada versión tiene canonical propio y enlaces recíprocos a los cuatro idiomas y a `x-default`. Las variantes antiguas conservan redirecciones y las URL inexistentes deben devolver un 404 real.

Los textos de las fichas se separaron en 28 archivos de idioma y documento. La portada no necesita descargar todos los servicios y un visitante de una ficha no descarga las traducciones de los otros tres idiomas. Las tipografías Inter y Playfair Display están alojadas localmente, con archivos WOFF2 y licencias OFL. Los nombres de fuentes y recursos compilados incluyen una huella de contenido para permitir caché prolongada.

Los tamaños exactos de los archivos y los resultados de Lighthouse se conservan en las evidencias finales. Los resultados de laboratorio no sustituyen los Core Web Vitals de usuarios reales; INP requiere interacciones y datos de campo. La API pública de PageSpeed devolvió HTTP 429 por cuota del servicio, por lo que no se atribuyen resultados a esa API.

## Medición de contactos

El código envía `page_view` para rutas conocidas, con idioma y canonical coherentes, y evita duplicados producidos por remontajes o repetición del evento SEO. GA4 no se carga en local ni en los dominios temporales de Vercel. Las URL enviadas no contienen parámetros de consulta.

`contact_email_click` representa un clic en email y `generate_lead` una respuesta satisfactoria del formulario. La prueba automatizada valida estos eventos, la navegación, la deduplicación, la exclusión de tráfico de pruebas y la ausencia de parámetros personales. No se envían mensajes reales a la traductora para probar el formulario.

La recepción en la propiedad de GA4 y su ajuste de cambios de página por historial deben verificarse en la propiedad correcta. La sesión de Analytics localizada inicialmente correspondía a Foco, un proyecto distinto, cuya configuración no se modificó.

## Verificación y publicación

Comprobaciones reproducibles:

```sh
npm run lint
npm run verify:analytics
npm run verify:content
npm run build
npm run verify:seo
```

El prerenderizado comprueba idioma, H1, contenido, título, descripción, canonical, hreflang, enlaces de idioma, schema y presencia de las respuestas FAQ. El verificador del artefacto comprueba el inventario, títulos únicos, recursos, enlaces internos y alcance de todas las páginas desde `/es`. Se genera un 404 con `noindex`.

Se verificó además que el arranque conserva el HTML inicial hasta cargar la página y las traducciones, evitando sustituirlo temporalmente por una pantalla de carga. La prueba local final obtuvo CLS 0, rendimiento 86 y 100 en accesibilidad, buenas prácticas y SEO, en un servidor estático sin compresión.

Se validó una primera versión mediante una URL de producción sin asignar el dominio principal, con páginas representativas de los cuatro idiomas, documentos, tarifas, redirecciones y errores. La versión final se publica desde GitHub Actions tras repetir todas las comprobaciones. Después se repite el rastreo HTTP en el dominio público. Los resultados, el commit y el identificador final se guardan en el archivo de evidencias.

GitHub Actions utiliza Node.js 22 y Vercel CLI 50.23.2. La CLI recibe el token mediante su opción `--token`, referenciada al secreto de GitHub; la variable de entorno por sí sola no autenticó la primera ejecución. La clave pública del formulario se conserva en `VITE_WEB3FORMS_KEY` como secreto de compilación de GitHub; el flujo falla si falta, para evitar publicar un formulario sin configuración. Los cambios exclusivos de documentación no vuelven a desplegar la web.

Durante la preparación, FileProvider de macOS retiraba las copias locales de archivos de Documentos que necesitaban Node y Git, bloqueando algunas lecturas. Se compiló y comprobó una copia estable en `/tmp/mctrad-release-workspace`. La igualdad de los archivos fuente se verificó por SHA-256; el inventario está en `source-sha256.json`. Se usó una copia limpia del mismo repositorio para enviar el commit y se sincronizó el historial del espacio de trabajo. Esta ubicación temporal es una medida de la sesión, no un requisito del proyecto.

## Seguimiento

Después de publicar, inspeccione la portada española, la alemana, la ficha alemana de matrimonio y la española de títulos con la prueba de URL publicada. Solicite indexación de las páginas importantes cuando la prueba sea correcta. El sitemap ya estaba registrado; reenviarlo no garantiza indexación.

Revise semanalmente indexación, posición por consulta, impresiones y contactos por página e idioma. Compare el rendimiento tras nuevos rastreos, separando consultas de marca de búsquedas de servicio. Google decide qué páginas indexa; superar los verificadores técnicos no garantiza posiciones ni una fecha de indexación.
